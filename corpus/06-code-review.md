# Code review

## Pull requests
Every change needs one approving review before merge; changes to authentication or billing code need two. Keep pull requests under 400 changed lines where you can.

## Turnaround
Reviewers should respond within one working day. If a review is blocked for more than two days, raise it in the team channel.

## Merging
Use squash merge. The main branch must stay deployable, so all checks have to pass. Never force-push to main.
